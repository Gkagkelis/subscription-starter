# CCE 0.1 — Ελάχιστες απαιτήσεις δεδομένων (MINIMUM_DATA_REQUIREMENTS)

Τι χρειάζεται ώστε η CCE να δίνει **ελληνικές** προβλέψεις για επισκευή, αντικατάσταση, refurbished, trade-in και εγγύηση.

## 1. Υποχρεωτικές ιδιότητες κάθε συνόλου δεδομένων

| Απαίτηση | Γιατί | Έλεγχος στον κώδικα |
|---|---|---|
| **Ατομικές επιλογές**, μία γραμμή ανά (ερωτώμενος, σετ, εναλλακτική) | Το μοντέλο μαθαίνει από επιλογές ανθρώπων, όχι από ποσοστά | `schema.validate`: ακριβώς μία επιλογή ανά σετ |
| **Μεταβαλλόμενα χαρακτηριστικά** εναλλακτικών (τιμή, κόστος επισκευής, trade-in, εγγύηση, παράδοση) | Χωρίς μεταβολή δεν ταυτοποιείται η επίδρασή τους | Ο σχεδιασμός ορίζεται εκ των προτέρων (`cce.design`) |
| **Επιλογή «καμία/αναβολή»** | Για να εκτιμηθεί ο όγκος, όχι μόνο η κατανομή | Εναλλακτική `none` |
| **Σταθερό ID ερωτώμενου** | Split ανά ερωτώμενο, panel mixed logit, bootstrap | `schema.validate`: κάθε σετ ανήκει σε έναν ερωτώμενο |
| **Χαρακτηριστικά ερωτώμενου** με τους ορισμούς του πάνελ | Σύνδεση με τους 500 συνθετικούς καταναλωτές | `cce/panel.py` |
| **Holdout σετ** εκτός σχεδιασμού και **επανάληψη** ενός σετ | Εξωτερική επικύρωση και test-retest | `task_type`: `holdout_*` / `repeat_of_*` (`cce.train`, `cce.ingest`) |
| **Άδεια** που επιτρέπει την εμπορική/ανατεθείσα χρήση· συναίνεση ερωτωμένων | Νόμιμη χρήση | Manifest: πεδίο `licence` |
| **Ελληνικός πληθυσμός** με γνωστό πλαίσιο δειγματοληψίας και ποσοστώσεις | Για τη σήμανση `IN_POPULATION` | `domain.populations` + `validation.external` |

## 2. Ελάχιστο μέγεθος

Υπολογισμένο από τον σχεδιασμό στο CHOICE_EXPERIMENT_DESIGN §4: 12 σετ ανά ερωτώμενο, 4 εναλλακτικές, 12 παράμετροι.

| Τι θέλουμε να ξέρουμε | Ελάχιστο N (κεντρικό σενάριο τιμής) |
|---|---|
| Μερίδια επισκευής / νέου / refurbished / αναβολής σε συγκεκριμένα σενάρια, ±5 μονάδες | ≈ 100–150 |
| Ευαισθησία στο κόστος επισκευής και στο trade-in | ≈ 300–900 |
| Αξία εγγύησης (≥ 60 € για 2→5 έτη) και παράδοσης (≥ 60 € για 10→1 ημέρες) | ≈ 1.070 (≈ 1.630 πεδίου με προσαυξήσεις) |
| Διαφορές 25% (κόστος επισκευής ή τιμή· trade-in ή έκπτωση) | ≈ 1.650–4.300 |
| Υποομάδες (π.χ. ευαισθησία τιμής ανά ηλικία ή εισόδημα) | ×(αριθμός υποομάδων) για ίδια ακρίβεια ανά υποομάδα |

**Δύο επιφυλάξεις για αυτά τα νούμερα**

- Εξαρτώνται από την **άγνωστη** ελληνική ευαισθησία στην τιμή. Αν είναι τόσο χαμηλή όσο στο ελβετικό πείραμα, οι στόχοι WTP χρειάζονται > 20.000 ερωτώμενους.
- Γι' αυτό το **pilot των 150** προηγείται και ξαναϋπολογίζει το N.

## 3. Τι ΔΕΝ αρκεί

- **Δημοσιευμένα ποσοστά** (π.χ. «το Χ% των Ελλήνων προτιμά επισκευή»· Eurobarometer, εκθέσεις). Δίνουν ένα σημείο, όχι πώς αλλάζει η επιλογή με την τιμή. Χρησιμεύουν μόνο ως εξωτερικό σημείο σύγκρισης.
- **Ερωτήσεις πρόθεσης ή κλίμακας Likert** χωρίς εναλλακτικές με χαρακτηριστικά.
- **Συνθετικά δεδομένα ή ετικέτες από LLM.** Δεν χρησιμοποιούνται ποτέ για εκπαίδευση.
- **Ξένα DCE χωρίς ελληνική επικύρωση.** Χρησιμοποιούνται μόνο:
  - ως `SOURCE_POPULATION_ONLY`·
  - ως priors σχεδιασμού.
- **Πωλήσεις λιανοπωλητή (revealed preference) χωρίς τις εναλλακτικές που είδε ο πελάτης.** Δεν ταυτοποιούν την επίδραση των χαρακτηριστικών.

## 4. Τι θα πρόσθετε αξία (προαιρετικά)

| Δεδομένα | Αξία | Προϋπόθεση |
|---|---|---|
| Δεδομένα συναλλαγών λιανοπωλητή **με τις προσφορές που εμφανίστηκαν** (τιμή, εγγύηση, trade-in, παράδοση ανά επίσκεψη ή καλάθι) | Revealed preference για βαθμονόμηση του stated preference μοντέλου, ειδικά της κλίμακας τιμής | Συμφωνία με τον λιανοπωλητή, ανωνυμοποίηση, νομική βάση GDPR |
| Αιτήματα επισκευής με προσφορά κόστους και την τελική απόφαση | Πραγματικό «επισκευή ή αντικατάσταση» σε πραγματικό κόστος | Το ίδιο |
| Eurobarometer microdata (GESIS) με Ελλάδα | Εξωτερικά σημεία σύγκρισης μεριδίων «επισκευάζω αντί να αντικαθιστώ» | Λογαριασμός GESIS από τον χρήστη |
| Πείραμα και για smartphone / TV | Δεύτερη κατηγορία· έλεγχος μεταφοράς μεταξύ κατηγοριών στην Ελλάδα (VALIDATION_REPORT §6) | Χωριστό block ή δείγμα |
