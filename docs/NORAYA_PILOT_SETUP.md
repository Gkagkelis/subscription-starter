# Noraya Pilot — οδηγός ενεργοποίησης

Αυτό το branch προσθέτει στο Noraya λειτουργία «πιλοτικού πελάτη» με ελεγχόμενο κόστος.
**Δεν αλλάζει τίποτα στη ζωντανή εφαρμογή μέχρι να γίνει merge στο `main`.**

Αντίγραφο ασφαλείας της έκδοσης πριν από τις αλλαγές: branch `backup/prin-to-pilot-2026-09-29`.

## Βήματα (με τη σειρά)

### 1. Supabase — νέοι πίνακες (μία φορά, ΠΡΙΝ από όλα τα άλλα)

Supabase → **SQL Editor** → New query → επικόλλησε **όλο** το αρχείο
`supabase/migrations/20260929000100_noraya_pilot_limits.sql` → **Run**.

Φτιάχνει **μόνο νέους** πίνακες και συναρτήσεις (`noraya_*`). Δεν αγγίζει κανέναν υπάρχοντα. Μπορεί να τρέξει ξανά χωρίς πρόβλημα.

**Σημαντικό:** τρέξε το SQL πριν ανοίξεις το link δοκιμής. Χωρίς αυτό, η εγγραφή με κωδικό δεν δουλεύει.

### 2. Vercel — μεταβλητές περιβάλλοντος

Vercel → Project → **Settings → Environment Variables**. Βάλ' τες πρώτα μόνο για **Preview** για να δοκιμάσεις, και μετά και για **Production**.

**Απαραίτητες:**

| Μεταβλητή | Τιμή |
|---|---|
| `NORAYA_ADMIN_EMAILS` | Το email με το οποίο μπαίνεις εσύ στο Noraya (πολλά χωρίζονται με κόμμα). Εσύ δεν έχεις όρια και βλέπεις το `/admin/pilot`. |
| `CRON_SECRET` | Ένα μεγάλο τυχαίο κείμενο (π.χ. 40 γράμματα/αριθμοί). Το Vercel το στέλνει αυτόματα στα crons. **Μόλις μπει, το `token=dev` σταματά να δουλεύει.** |

**Για την πληρωμή με κάρτα (€40):**

| Μεταβλητή | Τιμή |
|---|---|
| `STRIPE_SECRET_KEY` | Από Stripe → Developers → API keys (ξεκίνα με το test key `sk_test_...`). |
| `STRIPE_WEBHOOK_SECRET` | Stripe → Developers → Webhooks → Add endpoint: `https://<το-site-σου>/api/webhooks`, event **`checkout.session.completed`** → αντέγραψε το «Signing secret» (`whsec_...`). |

Η πληρωμή με κάρτα ενεργοποιείται **μόνο** όταν βάλεις και `NORAYA_DAY_PASS_STRIPE` = `on`. Μέχρι τότε (ή χωρίς Stripe), το κουμπί «Πλήρες ξεκλείδωμα» στέλνει **email σε σένα** ως αίτημα και το ενεργοποιείς χειροκίνητα από το `/admin/pilot`.

**Για τα email ειδοποιήσεων:** `RESEND_API_KEY` (υπάρχει ήδη για το welcome email). Προαιρετικά `NORAYA_ALERT_EMAIL` (αλλιώς πάει στο πρώτο email του `NORAYA_ADMIN_EMAILS`). Με τον δοκιμαστικό αποστολέα του Resend, τα email φτάνουν μόνο στο email του λογαριασμού Resend.

**Προαιρετικές ρυθμίσεις (με τις προεπιλογές τους):**

| Μεταβλητή | Προεπιλογή | Τι κάνει |
|---|---|---|
| `NORAYA_DAILY_LIMIT` | `3` | Χρήσεις ανά κατηγορία τη μέρα |
| `NORAYA_PASS_CAP` | `10` | Όριο ασφαλείας ανά κατηγορία με ξεκλείδωμα |
| `NORAYA_DAY_PASS_EUR` | `40` | Τιμή ξεκλειδώματος |
| `NORAYA_AUTO_DAILY_LIMIT` | `60` | Αυτόματες αναλύσεις τη μέρα |
| `NORAYA_SCOPE_DAILY_USD_CAP` | `15` | Ανώτατο κόστος AI ανά πελάτη τη μέρα ($) |
| `NORAYA_PASS_DAILY_USD_CAP` | `25` | Ανώτατο κόστος AI με ξεκλείδωμα ($) — πάντα κάτω από τα €40 |
| `NORAYA_CRON_DAILY_USD` | `3` | Ανώτατο κόστος AI των crons ανάλυσης τη μέρα ($) |
| `NORAYA_CLASSIFY_DAILY_USD` | `3` | Ανώτατο κόστος της ταξινόμησης ειδήσεων τη μέρα ($) |
| `NORAYA_DEMO_DAILY_USD` | `3` | Ανώτατο κόστος AI των σελίδων demo τη μέρα ($) |
| `NORAYA_AI_CRON_HOURS_UTC` | `4,10,16` | Ώρες (UTC) που τρέχουν τα ακριβά crons (07/13/19 ώρα Ελλάδας το καλοκαίρι) |
| `NORAYA_ADVISE_MAX_PER_RUN` | `4` | Γεγονότα με συμβουλή ανά αυτόματη εκτέλεση |
| `NORAYA_DEMO_DAILY_CALLS` | `40` | Κλήσεις AI τη μέρα από τις δημόσιες σελίδες demo (όλοι μαζί) |
| `NORAYA_INVITE_CUTOFF` | `2026-09-29T20:00:00Z` | Λογαριασμοί που φτιάχτηκαν πριν από αυτή τη στιγμή δεν χρειάζονται κωδικό (οι υπάρχοντες). Όποιος φτιάχτηκε μετά χρειάζεται κωδικό. |
| `NORAYA_INVITE_REQUIRED` | `true` | `false` = εγγραφή χωρίς κωδικό |
| `NORAYA_LIMITS_ENABLED` | `true` | `false` = χωρίς όρια (π.χ. όταν πληρώνει μηνιαία) |
| `NORAYA_PREFILTER` | `on` | `off` = χωρίς προφίλτρο άρθρων |
| `NORAYA_USD_TO_EUR` | `0.9` | Ισοτιμία μόνο για τον υπολογισμό κέρδους στη σελίδα admin |

Μετά από αλλαγή μεταβλητών στο Vercel χρειάζεται **Redeploy** για να ισχύσουν.

### 3. Κωδικός πρόσκλησης για τον πελάτη

Μπες στο `/admin/pilot` (με το email του `NORAYA_ADMIN_EMAILS`) → «Κωδικοί πρόσκλησης»:
- Κωδικός: κάτι μη προφανές, π.χ. `ELAS-7K4Q-2026`
- Πελάτης (group): `elas` (όλοι οι χρήστες του ίδιου group μοιράζονται τα ίδια όρια και το ίδιο ξεκλείδωμα)
- party_key: `elas` (προεπιλέγει το κόμμα στο onboarding)
- Μέγ. χρήστες: π.χ. `5`

Μπορείς να τον απενεργοποιήσεις όποτε θέλεις.

### 4. Δοκιμή στο link δοκιμής (Preview)

Κάθε push στο branch βγάζει δικό του link στο Vercel (Deployments → το τελευταίο του branch). Έλεγξε:

1. `/choose-role` → μόνο «Πολιτικό Κόμμα» ανοιχτό, τα άλλα «Σύντομα».
2. Εγγραφή με λάθος κωδικό → μήνυμα λάθους. Με σωστό → εγγραφή → onboarding → Strategy Room (χωρίς ψυχογράφημα).
3. Κάτω δεξιά «Χρήση σήμερα» με μετρητές.
4. 3 σενάρια → στο 4ο εμφανίζεται το μήνυμα με το «Πλήρες ξεκλείδωμα ημέρας — €40». Τα άλλα (π.χ. chat) δουλεύουν ακόμα.
5. Με Stripe σε test mode: πληρωμή με κάρτα `4242 4242 4242 4242` → ξεκλείδωμα → έρχεται email.
6. `/admin/pilot` → φαίνονται κόστος, χρήση, πληρωμή.
7. Ο δικός σου λογαριασμός δουλεύει όπως πριν.

### 5. Ανέβασμα στο live

Όταν είσαι ικανοποιημένος: merge του branch στο `main` (μέσω Pull Request). Αν κάτι δεν σου αρέσει μετά: Vercel → Deployments → προηγούμενο deployment → **Promote to Production** (επιστροφή σε 1 λεπτό), ή επαναφορά από το branch `backup/prin-to-pilot-2026-09-29`.

### 6. Δίχτυ ασφαλείας στο Anthropic

Console του Anthropic → **Billing / Limits**: βάλε μηνιαίο ανώτατο όριο ξοδέματος, και αυτόματη επαναφόρτιση αν τη θέλεις. Ό,τι κι αν συμβεί στον κώδικα, δεν ξεπερνάς αυτό το ποσό.

- Κάθε μη-admin λογαριασμός έχει τα ημερήσια όρια. Αν θέλεις κάποιον χωρίς όρια, πρόσθεσε το email του στο `NORAYA_ADMIN_EMAILS`.
- Στο chat, πολύ μεγάλο επικολλημένο κείμενο κόβεται στους 20.000 χαρακτήρες.

## Ένας έλεγχος που αξίζει να κάνεις

Κάποιες λειτουργίες αποθηκεύουν αποτελέσματα στον πίνακα `analysis_cache` και ελέγχουν πόσο «φρέσκα» είναι με τη στήλη `updated_at`. Ο πίνακας αυτός δεν υπάρχει στα migrations του repo. Τρέξε στο SQL Editor:

```sql
select column_name, data_type
from information_schema.columns
where table_name = 'analysis_cache';
```

Αν **δεν** υπάρχει στήλη `updated_at`, κάποιες αποθηκεύσεις (επιθέσεις, σενάρια, strategic image) δεν ξαναχρησιμοποιούνται και πληρώνονται ξανά. Στείλε μου το αποτέλεσμα και το φτιάχνουμε.
